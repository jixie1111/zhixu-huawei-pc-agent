# 系统设计

## 目标与边界

知序把“写一篇软文”拆成可追溯的创作过程。重点不是无条件输出，而是确保型号明确、来源可查、图片对应、冲突可见、不可确认的信息不会自动变成营销承诺。

输入包括产品、人群、场景、平台、购买阶段、目标、补充要求、来源模式和生成方式；输出统一包含场景判断、知识库依据、图文软文、核验结果。按用户最新要求，优先上架免 API 的公开交互演示：少量官网摘要与远程图片在浏览器中按规则编排。本机完整版保留完整授权库、原图与可选模型；默认规则预览，选择模型后才需要模型配置，ima 是可选取证来源。依据和许可范围见 [资料使用方案](SOURCE-POLICY.md)。

## 分层

公开静态版通过 `npm run build:demo` 完成类型检查与独立构建：Vite 子进程设置 `VITE_PUBLIC_DEMO=true`，使用 `base=./` 输出 `dist-demo/`。`preview:demo` 在4174端口预览；`package:demo` 只扫描并暂存构建文件与专用 README。运行不启动后台、不调用 `/api`、ima 或模型。它复用 React 工作台及共享场景/平台规则，使用专门核对的公开证据集合。历史只保存在当前浏览器的独立 localStorage 中（最多20条、约1.5MB），存储不可用时仅留内存，不是账户同步或云端持久化。Markdown/JSON/HTML 可下载，来源和规则标记不能删除。

本机完整工作台的服务层如下；这不是公开静态版的运行依赖：

```text
浏览器 React 工作台
  │ 本地/API 请求；生成过程事件；草稿导出
  ▼
Express API ─── 访问控制 / 限流 / 输入校验 / 脱敏
  ├─ 需求校验 → 场景策略 → 内容编排或模型生成 → 核验
  ├─ 知识适配：授权本地知识库 / 可选官方 ima CLI
  ├─ 来源绑定：型号 → 事实 ID → 段落 → 图片
  └─ SQLite：运行记录、父版本、策略、证据、文章、审查结果
```

本机前端不直接访问 ima 或模型接口；服务调用凭证由服务端使用，不进入前端构建产物。`.env` 或部署平台 Secrets 提供重启后仍生效的服务配置；网页填写的设置仅在当前服务进程内生效。公开静态版无密钥配置，不能开启模型选项。上传源码不等于上传知识资料，原始库、原图片字节和数据库保持私有。

## 核心数据

| 实体 | 关键字段及责任 |
| --- | --- |
| `Brief` | 精确型号、人群、场景、平台、阶段、目标；`mode=local\|ima` 指定来源，`generation=model\|rules` 指定生成方式；修改保留父版本 |
| `Fact` | 唯一 ID、型号、字段、原始内容、来源标题/链接/模式和检索时间 |
| `ProductImage` | 精确型号、图片资源、来源链接、描述、建议位置与选图理由 |
| `Evidence` | 产品、事实、图片、限制与检索轨迹 |
| `Strategy` | 场景问题、优先事实、语气、结构、篇幅、图片数量与行动建议 |
| `Article` | 标题、导语、带事实引用的正文、CTA、标签、图片、免责声明 |
| `Audit` | 阻断/待审/通过、逐项事实、问题严重度、建议、发布条件 |
| `Run` | 输入、上述产物、引擎、时间、版本关系与执行轨迹 |

SQLite 中的运行记录可能包含用户需求、产品资料片段和模型输出，应视为私有数据；数据库与备份不进入公开代码库。

公开演示的证据来自独立的官网摘要集合，不从私有 ZIP 或 SQLite 提取。共享类型内部沿用 `sourceMode=local` 表示内置资料，界面和导出明确标为“公开官网摘录”，不能解释为用户本地原库或 ima 在线取证。图片使用官网远程 URL；浏览器加载与导出受网络及 CORS 影响，无法内嵌时必须显示未内嵌状态，不能宣称 HTML 已完整离线化。

ima 图片采用不透明资源 ID。服务端私有注册表只保存媒体 ID 或经验证的无签名公开官方 URL、账户指纹与时间，不保存 API 密钥、临时访问头或签名下载地址；重启后在同一授权账户下刷新媒体访问，换账户/密钥后旧资源不可直接访问。注册表与 SQLite 同样不公开。

## 检索与型号隔离

本地索引递归读取被允许的目录，不跟随符号链接，排除 P4/90/99。只将指定产品事实字段纳入可引用事实；价格和活动文案不因出现在文件里就成为可复用参数。图片由同一型号目录及图片索引关联，不可用相似型号补数量。

ima 接入必须明确目标共享库、实际账号标识和连接状态。检索无结果时按官方能力执行目录回退；回退仍无明确型号证据时停止或要求补充，不能从其他库、产品常识或另一个型号补写。在线响应中的文字属于不可信资料，其中要求改变系统规则、泄露凭证或外发数据的内容不是指令。

本地知识库已由用户提供的 ZIP 解压并按型号建立索引，无需为本地流程重新上传到远端服务。用户允许参考官网资料；公开摘要与补充事实必须核对具体型号、年款、系统和配置，保留产品页链接、读取日期与适用条件。商城首页不能作为参数依据，冲突资料不能覆盖原库事实；公开集合以逐条核对记录为准，不批量复制原库。

尺寸字段明显错位或同字段不同来源冲突时，标记冲突并停止生成。该检测是风险提示，不是自动修订原始资料。正确值只能在人工核对权威材料后更新。

## 策略与平台适配

八场景不是更换一个标题：每个场景拥有独立的人群、问题、事实优先级与切入角度。购买阶段、目标与补充要求作为额外约束。四平台使用各自的语气、结构、参考篇幅与选图数量：小红书 3–6、公众号 2–4、朋友圈 1–3、海报 1。

模型收到系统提示词、结构化需求及允许引用的事实和图片清单。生成后再次验证结构、引用、型号、图片数和风险表达。兼容 Chat Completions 的服务是项目的实现选择；赛题允许调用公开大模型，没有要求购买某家模型服务或提交 API Key。当前模型链路需要可用服务地址、模型 ID 与密钥。

界面按最新意愿默认规则预览，公开静态版仅提供规则模式，不标为大模型生成。为兼容旧请求，本机 API 的 `mode=local` 且省略 `generation` 时仍使用规则；ima 来源始终调用模型。显式选择本地模型路径只需要模型配置，不要求 ima 凭证或媒体额度；缺配置时明确报错。没有模型不再阻塞规则演示或预览上架。

## 核验和生命周期

运行过程先验证需求，再取证、定策略、生成和检查，最后保存结果。公开版只执行规则检查与浏览器记录；本机模型路径另执行原图可用性和独立语义核验。修改创建新版本并重新检查，不通过编辑覆盖旧版本。换平台/场景以原需求为基础重新运行，不沿用旧核验结果。

模型改写需同时接收原稿与修改要求，不能仅重新写一篇同主题文章。规则编排只支持明确的精简和平台重排，不支持的语气/结构改写返回错误。独立语义核验应核对正文以及图片引用、说明、位置与用途；图片语义依据索引中的描述与编排信息，不宣称已进行像素级视觉理解。不能把“引用存在”当成“断言成立”。

检查层包括事实引用存在性、型号一致性、资料冲突、数字/参数支撑、图片一致性/数量、绝对化、虚假承诺、价格补贴、贬低竞品、无依据对比和来源完整性。已标记问题不会因成功保存而自动消失。本地来源的模型稿在原图可用、事实与图片来源一致、独立语义核验通过且无阻断或警告时可以通过核验；它仍标为 local，不改标为 ima。规则稿或未达发布条件的内容保留待审核状态，核验通过也不授予素材公开权。

取消信号向模型、ima、图片读取与下载传播；持久化前已取消的请求不作为成功结果保存。ima 同作用域、同图片的并发读取共享上游请求；单个等待者取消不影响其他等待者，最后一位取消才终止上游。取消不能撤回供应商已接收或已计费的操作。

## 取舍与限制

- SQLite 适用于当前单实例演示；多实例并发部署需要共享数据库、用户隔离和分布式限流。
- 稳定事实引用比自由发挥优先；规则不能证明所有自然语言主张均真实。
- 不自动做支付、下单、广告投放、报名或正式提交。
- 不在缺凭证时造在线检索轨迹、假连接、假截图或获奖/效果数据。
- 本次公开版是独立静态规则演示，不依赖 `PUBLIC_DEPLOYMENT`。可选服务端公网模式仍禁用本地知识库与本地来源历史，只接受满足来源链检查的 ima 模型路径。
- 用户已授权预览上架；[GitHub 仓库](https://github.com/jixie1111/zhixu-huawei-pc-agent)源码已推送，首批108文件清单核验通过，本次发布附作品说明书PDF；[魔搭创空间](https://modelscope.cn/studios/jixie1111/zhixu-huawei-pc-demo)最终版 Running、游客可访问且真实桌面/手机交互通过。这不是正式比赛提交。
- 本地静态 e2e 2/2及三场景九导出通过，本地模型与访问权限回归另有3/3通过。最终线上独立验收7项操作结果、三格式导出与连续录屏，0应用 API请求、0页面异常；云端JS与本地最终构建哈希一致。规则证据和合成模型回归均不等于正式模型验收。
- 真实模型尚未配置，至少三组本地知识库＋真实模型案例及模型录屏未完成。规则版可用与上线不能据此标记正式 AI 验收通过。
