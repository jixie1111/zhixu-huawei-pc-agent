# 系统设计

物有言将门店营销创作拆分为需求确认、证据检索、创意选择、生成、独立核验和版本交付。界面共用，公开静态体验与本机模型服务保持明确边界。

## 公开静态体验

`src/Studio.tsx` 默认打开 `DirectorStudio`，经典表单作为次级入口。通过 `src/api.ts` 将请求分派到浏览器内的 `demo-adapter`；这不是 HTTP 模型服务。

- `src/demo-evidence.ts` 保存独立核对的官网摘要与图片 URL，不从私有库提取。
- `shared/director-rules.ts` 与本机服务共享确定性的需求识别和三个预设策划方向。
- `src/demo-director.ts` 维护有界、30 分钟有效的方案缓存，绑定需求、精确型号、事实和所选方向。需求变化、跨方案引用或过期均须重新策划。
- 规则成稿绑定公开事实 ID，三种方向采用不同开头、事实次序和行动引导，始终标为规则体验。
- 历史存入独立 localStorage，最多 20 条、约 1.5 MB；只保存正文、输入和有界方向选择。刷新时重新读取当前公开证据并核验，不信任缓存中的来源 URL。
- 官网图直接加载；缺图显示占位。导出为 Markdown / HTML / JSON，HTML 尽力内嵌同型号官网图片。
- 本机模型、人设、生态、PNG 包等静态环境不支持的功能不展示为可用操作。

普通服务端公网模式仍走其原有访问控制，不能借公开静态适配读取私有内容。

## 本机服务

```text
React 工作台
  → Express：输入校验、访问控制、取消、阶段事件
  → 导演：理解需求 → 必要确认 → 三种创意及历史相似度检查
  → 检索：授权本地库 / 可选 ima
  → 生成：规则编排 / 显式选择的真实模型
  → 核验：事实、原图、表达风险；模型路径另有语义核验
  → 有界局部修订 / 人工编辑
  → SQLite 版本记录及图文导出
```

本机导演默认选择模型；选择模型但缺配置或调用失败时明确报错，不偷偷回退为规则。前端不直接读取模型密钥。

需求、方案和所选方向在服务端绑定；方案也绑定证据指纹。事实变化后旧方案失效。模型生成仅可使用所选型号的事实与图片清单，人设只影响语气、结构和行动引导。

## 核心数据

| 类型 | 责任 |
| --- | --- |
| Brief / IntentProposal | 精确型号、受众、场景、平台、目标、必要确认及引擎 |
| CreativePlan / DirectorDecision | 三个方向、允许事实、选中方向、过期时间与决策依据 |
| Evidence / Fact / ProductImage | 型号、事实 ID、原始依据、适用条件及对应图片 |
| Article / Audit | 带引用的正文、图文编排、核验结果和待处理问题 |
| Run | 输入、作品、证据、引擎、时间及父版本 |

本地索引排除受控目录、不跟随符号链接，不合并相似型号。存在参数冲突时保留冲突并阻止创作；不会由模型自行改写来源。

## 核验与版本

规则层检查引用、型号、数值、图片、平台要求、夸大承诺、权益和来源完整性。真实模型路径另有独立语义核验、原图可用性检查和有界局部修订。图片索引与人工复核注释不等于自动像素级事实证明。

编辑与改写均创建新版本，不覆盖旧稿；平台转换重新编排并核验。规则只支持确定性的精简与平台重排，其他自由改写需模型或人工编辑。

多平台内容包记录各平台结果、部分失败与取消。生态创作要求具体设备、系统版本、关系来源和使用条件，不能泛化为所有华为设备均可互通。

取消传播至模型、ima 与图片读取；已取消的运行不作为成功作品保存。取消不能撤销供应商已接收或计费的请求。

## 发布边界

公开代码与说明书不附带授权知识库、原图字节、数据库、模型实际输出或凭据。公开页面不连接用户的 localhost。SQLite 和单机缓存适用于当前单实例；多店规模部署仍需账户隔离、共享存储和并发治理，当前没有千店规模实测。

具体配置见 [部署指南](DEPLOYMENT.md)，资料与授权见 [资料政策](SOURCE-POLICY.md)，验证范围见 [测试记录](TEST-REPORT.md)。
