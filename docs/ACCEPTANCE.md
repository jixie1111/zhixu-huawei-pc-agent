# 验收说明

本文件描述检查方法，实际结果单独写入 [测试记录](TEST-REPORT.md)。

## 当前完整版的自动化回归

```powershell
npm run check
npm run test:e2e
```

- 单元与接口测试使用合成资料，验证输入校验、检索、模型契约、核验、修订、权限和导出。
- 完整发布专项测试验证授权包的路径、文件哈希、作品计数、发布原稿保护、访客作品隔离和模型连接隔离。
- 知识库测试覆盖 Windows / Linux 图片编号一致性，保证已发布作品的原图引用跨系统仍有效。
- 本机浏览器回归分桌面和手机，运行独立合成服务，不使用真实账号或模型。
- Windows 浏览器默认使用本机 Edge，可由 PLAYWRIGHT_CHANNEL 指定已有 Chromium 通道。

## 完整版原地址上线检查

当前魔搭使用 Docker 运行同一套 React / Express 服务，而非单机型静态演示。在线检查使用真实响应，不拦截网络、不注入替代资料：

1. 原地址打开新版导演首页，确认 12 款机型、1345 份已索引资料、61 张绑定原图；资料包仍包含全部 1538 个文件。索引过滤规则与本机一致。
2. 核对 52 份单品作品、4 个多平台内容包与 2 份生态作品。逐条比较发布快照，保留原版本、生成方式和核验状态。
3. 实际请求全部 61 张绑定原图，并从历史作品导出 HTML 与 PNG 配图包，检查文件内容与图片可读性。
4. 新访客的模型 API 地址、模型名称和 API Key 初始为空且可编辑。使用合成测试值验证保存、清除与访客隔离，不调用真实模型；状态接口和浏览器存储不得包含测试密钥。
5. 检查桌面以及真实手机设备仿真；同时核对魔搭外层页面与应用 iframe 的宽度、菜单和机型卡片。
6. 分别记录本应用与有明确来源的平台页面异常。应用异常或未知来源异常令验收失败；不能用平台 Running 或单个 HTTP 200 代替验收。

平台令牌和私有运行报告不写入公开记录；模型是否配置与已发布历史模型作品分开核对。

## 备用静态版检查

以下检查仅针对保留的静态规则备用版，不代表当前魔搭完整版：

```powershell
npm run build:demo
npx playwright test --config tests/e2e/demo.config.ts
npx tsx tests/public-demo-live.ts https://jixie1111-zhixu-huawei-pc-demo.ms.show/
```

其中 public-demo-live.ts 仅适用于目标地址实际部署静态版的情形，不能用它验收当前完整后端。需要平台访问参数时，可传入私有部署结果 JSON，不写入公开报告。

静态测试覆盖导演入口、三种写法、生成、编辑、三种导出、刷新历史和经典入口。故障测试主动阻断远程图片时，仅验证占位与缺图提示，不作为实际图片可达性证据。

## 真实模型验收

以下脚本需有权使用的资料与明确的运行授权，实际调用可能消耗模型额度：

- `scripts/verify-real-model.ts --run`：实际模型生成与核验记录。
- `tests/real-director-live.ts --run`：本机新版导演的真实浏览器链路。
- `tests/real-delivery-live.ts --run`：多平台和生态交付。
- `scripts/verify-real-ecosystem.ts`：限定设备与条件的生态验证。

运行前查阅各脚本的参数；模型、输入、原始结果、失败、修订和导出保存在私有目录。恢复旧稿、重新核验和全新模型生成分开统计，不相加冒充新生成。单次时长不作为稳定速度承诺。

此次完整发布保留空白模型连接，不使用项目持有人的个人凭据发起云端模型调用。真实模型创作需工作人员填写获授权的连接后运行；历史原稿、合成接口测试与规则体验均不计为本次新模型生成。
