## 公开规则版录制前

从实际发布并验证可访问的静态地址打开页面；链接未验证前不称已上线。使用公开版提供的少量官网摘要与远程图片，确认来源可打开、图片型号一致，并看到“规则演示／非大模型生成”标识。不需要模型或 ima 账号。准备开学季×小红书、职场办公×公众号、门店到访×朋友圈三组输入；这些是规则交互案例，不计入正式模型案例。依据见 [资料使用方案](SOURCE-POLICY.md)。

本地预演使用 `npm run build:demo` 和 `npm run preview:demo`，地址为 `http://127.0.0.1:4174`；`npm run package:demo` 只准备静态上传包，不上传。目前 [GitHub 仓库](https://github.com/jixie1111/zhixu-huawei-pc-agent)已创建待推送，[魔搭创空间](https://modelscope.cn/studios/jixie1111/zhixu-huawei-pc-demo)首版已 Running、首页HTTP200。修正版已完成本地构建并在第二次部署中；最终线上交互待验证，首页可访问不能替代完整演示录制。

已有本地公开规则版三场景九导出位于 `output/public-demo/`，HTML内嵌图分别3/3、2/2、1/1且0 API调用，另有桌面/手机 e2e 2/2与额外补测3/3通过。这些可作为规则版讲解证据，但不能当作第二次部署后的视频或正式模型录屏。

## 公开规则版建议流程

1. 作品介绍：知序将场景策略、证据、图文和检查统一在一个工作台；明确当前是纯浏览器规则演示，没有真实 LLM 或 ima 调用。
2. 展示资料边界：查看具体官网出处与远程图片来源，说明公开版仅含少量摘要，不包含用户完整知识库、原图片字节或密钥。
3. 进入创作工作台：先演示信息不完整时的提示，再填具体型号、人群、场景、购买阶段、目标和平台。
4. 开始创作：操作实际规则编排，展开知识依据检查产品与图片来源。不把本地计算进度讲成云端模型推理或实时 ima 检索。
5. 展示结果：标题、导语、段落、CTA、标签、图片、插入位置和理由；切到策略和核验面板解释依据。
6. 换场景：保持型号，切到职场办公/公众号，比较问题、结构、事实重点与配图数量；形成第二组结果。
7. 换平台：切到门店到访/朋友圈形成第三组；再转海报，展示单主视觉和最多三个卖点。
8. 干扰测试：要求使用绝对化、未经授权价格/补贴、竞品贬低等；展示系统拒绝或核验阻断。不要把这些测试文字发布到外部平台。
9. 修改：编辑正文或执行支持的精简/平台重排，保存并重新进行规则检查；说明任意语气、结构自由改写需要本机可选模型，不把有限规则能力讲成通用模型能力。
10. 导出：展示统一的场景判断/知识依据/图文/核验结构与来源标记。草稿须保留待审提示。
11. 结束：如实说明规则检查不等于独立模型核验，正式 AI 案例尚待完成；展示已验证的仓库/应用链接。此次是预览上架，不是正式提交。

## 本机真实模型验收另录

使用已索引的本地授权知识库，显式选择模型创作并配置可用模型；不需要 ima 额度。录制真实模型连接、同三组场景/平台生成、原图核对、独立语义核验、自由改写及导出，保留 local 来源与实际模型名称。若选 ima 才另外展示脱敏账号、共享库与真实检索。失败必须如实保留并修复，不能用公开规则结果替换。这组模型案例与录屏目前待完成，不作为规则预览上传的前置条件。

## 留存清单

记录实际日期、应用版本、输入与结果、来源模式、引擎、截图/录屏和具体来源；本机模型另保留运行 ID、模型与版本链。公开规则演示证据与私有模型证据分开存放，后者不随源码打包。录屏不得包含密钥、私有库完整目录或其他用户内容。

浏览器自动化可以记录实际应用的连续运行，不需要 computer use；应说明操作方式，不能拦截真实接口换成合成数据。3101 合成回归截图/trace/video 只能作 QA。公开规则录屏须标为“规则演示，非模型生成”；本地知识库＋模型录屏保留 local 来源与实际模型标识，两类证据不能混用。
