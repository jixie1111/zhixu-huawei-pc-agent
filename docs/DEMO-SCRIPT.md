# 物有言复赛演示脚本

## 复赛视频主线（2026-10-20 改版后）

手册要求视频是真实运行录屏，展示输入任务、调用知识库、生成图文及核验结果，并补充换场景或换平台；允许必要剪辑，但不能用剪辑掩盖人工代写或固定结果。群公告补充：可以加口播、亮点介绍。建议主片 3–4 分钟，这是制作建议，不是官方时长。

主线对着企业的三个问题讲：**店员一句话就能用、每家店写出来不一样、卖点有出处不乱说。**

| 段落 | 画面与口播要点 | 证据与限制 |
| --- | --- | --- |
| 约15秒开场 | 口播企业原话里的三个困境，接首页：产品主视觉、12 款机型、1345 份资料、61 张原图。 | 数字来自首页实时统计；情景演绎要标注。 |
| 一句话需求 | 点选 MateBook 14 酷睿 Ultra，输入“开学季，给大学新生写一篇小红书，邀请他们到店体验”。智能体整理简报，选人设“数码朋友”，填门店名。 | 真实模型，保留 local 来源与模型名；不展示密钥、终端或 JSON。 |
| 三种写法 | 展示三个创意方案，选推荐或另一个。 | 方案由模型生成，不是预设。 |
| 智能体流水线 | 7 步依次点亮：理解需求 → 策略 → 检索知识库 → 配图 → 撰写 → 核验 → 保存，计时器走动。 | 只由服务端真实事件驱动；等待可加速，但要标“已加速”。 |
| 看成品 | 手机框里的小红书预览：标题、同型号原图、正文；点“事实依据”看原文来源；切到“核验结果”。 | 不加“100%准确”字样；屏幕演示图不说成实拍。 |

### 录制前冻结与操作

1. 先 `npm run build`，再 `npm run start:local -- -Port 3003` 启动带模型的本机服务，用 `npm run check:local` 确认模型配置；连接测试成功也不替代完整生成。录制期间不改服务端文件，避免热重启使方案失效。
2. 先核对精确型号资料无冲突；四款PC冲突保留，不为演示强行放行。Pura80/MatePad仅作补充，不抢主线。
3. 另存一份完整、连续、无接口替换的原始录屏。主片若压缩等待，明确“真实等待加速/已剪辑”，不要将2-3分钟调用剪成未标注的“10秒生成”。
4. 不把恢复旧稿或原文重审说成全新生成。实际页面已从头生成通过：high案例140.894秒、low两次85.362与89.382秒；录制另测当次耗时，不作为稳定速度保证。当前本机会话请求low，重启后需确认环境或重新设置。
5. 失败原样保留；模型超时有明确提示，可稍后由操作员选择重试，不自动替成规则结果。录入密钥过程不进镜头。
6. 完稿同时保留原图、来源与所有配置/系统条件；复制和导出不去除草稿标识。生态关系到期须复核。

## 公开规则版建议流程

1. 作品介绍：知序将场景策略、证据、图文和检查统一在一个工作台；明确当前是纯浏览器规则演示，没有真实 LLM 或 ima 调用。
2. 展示资料边界：查看具体官网出处与远程图片来源，说明公开版仅含少量摘要，不包含用户完整知识库、原图片字节或密钥。
3. 进入创作工作台：先演示信息不完整时的提示，再填具体型号、人群、场景、购买阶段、目标和平台。
4. 开始创作：操作实际规则编排，展开知识依据检查产品与图片来源。不把本地计算进度讲成云端模型推理或实时 ima 检索。
5. 展示结果：标题、导语、段落、CTA、标签、图片、插入位置和理由；切到策略和核验面板解释依据。
6. 换场景：保持型号，切到职场办公/公众号，比较问题、结构、事实重点与配图数量；形成第二组结果。
7. 换平台：切到门店到访/朋友圈形成第三组；再转海报，展示单主视觉和最多三个卖点。
8. 干扰测试：要求使用绝对化、未经授权价格/补贴、竞品贬低等；展示系统拒绝或核验阻断。不要把这些测试文字发布到外部平台。
9. 修改：编辑正文或执行支持的精简/平台重排，保存并重新进行规则检查；说明任意语气、结构自由改写需要本机可选模型，不把有限规则能力讲成通用模型能力。
10. 导出：展示统一的场景判断/知识依据/图文/核验结构与来源标记。草稿须保留待审提示。
11. 结束：如实说明规则检查不等于独立模型核验，正式 AI 案例尚待完成；展示已验证的仓库/应用链接。此次是预览上架，不是正式提交。
