## 单机运行

1. 安装 Node.js 22.13+（22.x；本地验证版本22.23.1），在项目根目录运行 `npm ci`。
2. 将 `.env.example` 复制为 `.env`，填写本机需要的配置。
3. 使用已解压至 `private/knowledge` 的本地授权知识库，运行 `npm run knowledge:inspect` 核对索引；迁移机器时仅在获授权的私有目录部署该库，不重复上传到远端服务。
4. `npm run check` 完成编译和单元/接口检查。
5. `npm run dev` 用于开发；`npm run build` 后 `npm start` 用于生产预览。
6. 默认本地知识库＋规则预览，无密钥即可操作；需要模型创作时再显式选择模型、配置并测试。只有使用可选 ima 来源时才配置其账号、成员权限与 CLI；对照 [验收操作](ACCEPTANCE.md) 分别验收。

默认只监听回环地址。不要将开发服务器直接转发到公网。

| --- | --- | --- |

## 可选服务端容器运行（非本次静态上架）

项目的 Dockerfile 使用 Node 22、非 root 运行账户、端口7860和 `/mnt/workspace/zhixu` 数据目录。`.dockerignore` 排除知识库、凭证、ZIP/PDF、本机供应商目录、数据库、测试输出和构建缓存。构建阶段从官方地址下载固定版本 ima CLI 并核验摘要，不读取本机凭证。镜像构建尚需在具备 Docker 的环境实际验证，源码存在不等于部署成功。

```powershell
docker build -t zhixu-preview:local .
```

本地容器预览需显式挂载命名卷，例如 `--mount type=volume,source=zhixu-data,target=/mnt/workspace/zhixu`；魔搭使用平台提供的 `/mnt/workspace`，Dockerfile 不声明内层匿名卷，以免覆盖平台持久目录。

以下是当前公网 ima 路径的配置：通过平台 Secret 配置 `IMA_OPENAPI_CLIENTID`、`IMA_OPENAPI_APIKEY`、`LLM_API_KEY`、`ADMIN_TOKEN`，普通环境项配置 `IMA_KB_NAME`、`LLM_BASE_URL`、`LLM_MODEL`。本机本地模型路径不要求 ima 配置。不要把密钥拼进截图里的终端命令。

供应商 ima CLI 不在源码预览包中，但 Docker 构建会下载到 `/opt/ima`，并随构建出的运行镜像提供。源码公开与第三方软件再分发许可需分别确认；如不能在目标镜像内分发，请改为已获许可的只读挂载方式。数据目录需可写，实际宿主挂载权限须匹配容器中的 `node` 账户；平台挂载可能覆盖镜像中的目录权限，必须在实际部署时检查。

服务端公网容器的环境必须包括：

```text
HOST=0.0.0.0
PORT=7860
PUBLIC_DEPLOYMENT=true
DATA_DIR=/mnt/workspace/zhixu
IMA_SKILL_PATH=/opt/ima/ima_api.cjs
```

`PUBLIC_DEPLOYMENT=true` 会禁止本地快照与网页修改服务凭证。管理员令牌用于受控操作，不能打包进前端；评委访问方式需在平台访问控制与本应用令牌策略之间协调。不要通过去掉鉴权来解决“无需额外授权”要求，应在获得素材/服务授权后提供明确的评审专用访问方案。

## 可选服务端的反向代理来源与嵌入预览

以下仅适用于另行启用服务端的公网部署，不是本次静态托管配置。服务端需把 `PUBLIC_ORIGIN` 设为**应用实际运行页面**的完整 HTTPS 来源（协议、域名、可选端口），不是魔搭创空间介绍页，也不是容器内的 `http://...:7860`。例如应用地址为 `https://your-app.example.com/some/path`，应设置 `PUBLIC_ORIGIN=https://your-app.example.com`；示例域名必须换成实际地址。来源不含路径、查询参数、凭据或通配符。

当前前端使用根路径 `/api/...`，生产静态资源也从应用根目录加载。应使用平台提供的独立应用来源；若只有路径前缀代理，需明确做路径重写或另行实现 base path 支持，不能只改 `PUBLIC_ORIGIN` 就认为已兼容。

应用只用这个显式来源校验公开浏览器写入，不信任 `Forwarded`、`X-Forwarded-Host` 或 `X-Forwarded-Proto`，因此代理改写内部 Host 不会迫使我们放宽跨站限制。未配置 `PUBLIC_ORIGIN` 时状态与界面预览仍能读取，但带 Origin 的写入会返回 `ORIGIN_DENIED`；无 Origin 的服务端调用仍需管理员令牌和 JSON，不能绕过鉴权。不要设置 `trust proxy=true` 来规避来源错误；其安全前提见 [Express 官方反向代理说明](https://expressjs.com/en/guide/behind-proxies/)。

默认 `FRAME_ANCESTORS` 留空，响应使用 `frame-ancestors 'none'` 和 `X-Frame-Options: DENY`。只有确实需要门户 iframe 预览时，才在 `PUBLIC_DEPLOYMENT=true` 且 `PUBLIC_ORIGIN` 已设置后，填写**实际父页面**的明确 HTTPS 来源，最多 8 个、以逗号分隔。例如确认父页面来自这两个来源后可设置 `FRAME_ANCESTORS=https://modelscope.cn,https://www.modelscope.cn`，不要盲目添加未知来源或使用 `*`/`https://*.example.com`。嵌入白名单与写入白名单相互独立：允许魔搭页面嵌入，不代表允许魔搭来源直接跨站调用本应用 API。

启用明确嵌入白名单后仅保留对应 CSP `frame-ancestors`，移除冲突的旧 `X-Frame-Options`；需使用支持 CSP 的现代浏览器。多层嵌入的每一层祖先都必须获准，规则见 [W3C CSP 规范](https://www.w3.org/TR/CSP/#directive-frame-ancestors)。若浏览器报祖先来源或 `Origin: null`，先核对门户实际地址和 iframe sandbox，优先打开应用独立页面；不得允许 `null` 或放宽通配来源。本地模式两项均保持空值，禁止被外站嵌入。

部署后分别测试应用独立地址与门户 iframe：授权同源写入成功；其他来源、错协议/端口和伪造 forwarded 请求失败；未获准父页面不能嵌入。响应头契约测试不等于云端浏览器实测，仍需在目标平台完成这些检查。

公开模式在构造知识库时不扫描本地目录，展示、检索、生成与独立核验均以源码中的非敏感公开型号名称清单选型；即使误挂载了原始 ZIP 或快照，也不会启用本地知识读取或本地生成。误挂载旧 SQLite 时，本地或混合来源作品不会出现在公开实例的历史列表中，详情、导出、编辑、作为在线改写原稿也均被拒绝；缺失父稿、循环或超过100层的旧版本链按不完整来源拒绝，原数据不删除。原始资料能否另行公开或上传仍需单独取得授权，不能把此隔离策略当作上传许可。

本地和 ima 模型生成均先检查模型名称、密钥和官方端点配置，再读取证据；在 ima 路径缺少模型配置时不会先消耗检索额度。本地路径不检查 ima 额度。这只是静态配置前置检查，不代表模型余额或权限已验证。

## 本机离线备用演示

在本地模式、已有授权知识库且存在无冲突/有事实/至少三张有效原图的型号时，显式运行 `npm run demo:offline`。也可直接调用 `npx tsx scripts/prepare-offline-demo.ts --prepare --product-id <型号ID>`，或加 `--knowledge-dir <已授权的本地资料目录>`；型号ID可由本地索引检查获得。禁止在公开实例运行，不会回退联网。

产物位于 `DATA_DIR/demo-<时间>/`（默认 `private/demo-<时间>/`），共9个文件：纯 HTML 导航、三份全图内嵌 HTML、三份输入/审核 JSON、使用边界说明、SHA-256清单。打开 `index.html` 无需服务、令牌或网络。脚本只编排当前选定型号引用到的内容，不打包完整原库，不写入SQLite，不复制服务凭据或绝对 `sourcePath`，已存在目录拒绝覆盖。

三份内容分别是开学季小红书、职场办公公众号、门店到访朋友圈，均永久标注本地规则草稿、非ima在线取证、非模型生成、非正式案例，保留原有审核阻断/待复核项，不把规则编排当成正式验收通过。离线包仍包含选定事实与图片，必须留在私有目录；对外展示需额外取得许可，不能直接放进源码仓库或公开静态目录。

准备完成后，将占位目录替换为本次生成的私有目录，运行：

```powershell
npm run demo:verify -- "private/demo-<时间>"
```

验证器先核对8个载荷文件的字节数与SHA-256，再以断网浏览器打开目录和三份内容，检查桌面/手机尺寸的导航返回、全部内嵌原图解码、审核折叠区、离线声明与页面溢出，同时拒绝HTTP/HTTPS外部请求。Windows默认使用已安装的Edge，其他系统需有Playwright可用的Chromium；如需其他已安装通道，可设置 `PLAYWRIGHT_CHANNEL`。截图和报告写入 `tmp/offline-demo-qa/`，其中可能包含私有图片与文字，不能上传到源码仓库。此验证不会启动本地服务、调用ima或模型，也不是正式在线验收。

另外人工核对场景、平台与审核简报，再与真实模型运行证据分开保存。损坏或缺失图片、安全扫描失败时不会生成看似完整的包；磁盘写入失败可能留下不完整的新目录，未确认全部清单前不得用于演示。该备用包不能替代现场新任务生成、正式三组本地知识库＋真实模型案例或连续真实操作视频。使用实际服务、资料和模型的浏览器自动化录屏可以作为真实证据，需说明操作方式；mock/3101 QA 录像不能替代。

## ima CLI 的可复现安装

该步骤仅用于可选 ima 来源和当前 Docker 公网路径，本机本地知识库＋模型流程不需要安装 ima CLI。

脚本只从固定官方地址获取已核对的1.1.10包，校验SHA-256后提取允许列表中的文件；遇到内容不同的已有目录会拒绝覆盖。摘要是本项目核对官方包时记录的内容指纹，并非厂商数字签名。它不包含账号密钥，也不会自动加入共享库或增加API额度。

```powershell
New-Item -ItemType Directory -Path vendor -Force | Out-Null
npx tsx scripts/install-ima.ts --download --target vendor/ima-runtime
npx tsx scripts/install-ima.ts --check --target vendor/ima-runtime
```

随后将 `IMA_SKILL_PATH` 设为 `vendor/ima-runtime/ima_api.cjs`。已有官方归档可使用 `--archive <已授权的本地ZIP路径>` 代替 `--download`。`--verify-only` 只核验包，不创建安装目录。不要将下载所得文件或真实凭证误加入源码包。

## GitHub 与魔搭上传检查

## 运维与故障

本地主流程失败时先核对授权库索引、原图有效性，以及模型端点、模型名称、密钥、权限、额度和出口网络。缺少模型配置时明确报错，不静默退回规则。可选 ima 连接失败再核对同一账号是否加入共享库、Client ID 与 Key 是否配对、库名是否完全匹配、CLI 路径及网络；ima 限额不影响本地证据读取。错误日志只保留脱敏信息。

客户端能打开资料，只能证明客户端当前访问可用，不能证明 ima OpenAPI 的媒体取回额度仍可用。若官方接口明确返回资料次数上限，应停止反复请求，保留脱敏错误码、时间和接口名称向供应商确认。现有资料没有证实充值/会员可以提高 `get_media_info` 额度，也没有确认准确重置时刻；不要据此付费、轮换账户/密钥绕限或把本地快照冒充在线读取。

应用当前在收到明确当日额度错误后使用同账号的进程内24小时冷却；这是一项防重复请求策略，不是供应商重置时间承诺。图片索引持久化只保留受控引用，原图缓存60秒后或服务重启后，打开历史、预览图片、HTML导出和编辑核验仍可能触发媒体读取；限额时不能保证这些在线图片操作可用。无需第三方调用的断网展示应使用已核对完整内嵌原图的本地备用包，且保留来源模式标识。

同账号、同知识库和同图片的并发读取现在共享一次正在进行的链接/图片请求；不同作用域和不同图片不会混用，失败后也不自动重试。这只能减少重复调用，不会解除额度。开发服务会忽略private/tmp/output等生成物的文件变化，避免保存HTML草稿时自动重载编辑器；这些目录也不由Vite静态服务公开读取。

实际部署还需检查流式响应不被代理缓冲或提前超时、子路径代理是否重写正确、私有卷权限与容量，以及重启后的Secret/CLI/SQLite/私有图片映射是否完整。下载域名使用可取消的 DNS A/AAAA 查询，目标环境需能正常解析，不能依赖本机 hosts 覆盖。当前请求限流按直连地址计数，反向代理下可能聚合为一个出口地址；不要为规避限流而盲目信任任意 forwarded 头，应在已知部署网关上配置明确的身份/访问预算。

修改 `.env` 或部署 Secret 后重启实例；网页临时凭证在重启后消失。`DATA_DIR` 中除SQLite外还保存私有ima资源映射，ima 来源旧作品的图片需要该映射和相同授权账户恢复；本地来源图片需要对应的授权库与原图。不含API密钥的数据文件仍不应公开。备份时仅复制停止写入后的数据库或使用 SQLite 正确的备份方式，不要只拷贝一个仍在写入且有 WAL 的主数据库文件。

回滚应保留旧源码版本、配置版本和数据库备份。不要在生产环境运行删除 `private/` 或数据卷的清理命令。发布草稿不需要清除历史。

公开静态版的访问与交互验收只证明规则演示可用，不能代替真实模型验收。本机完整版的真实模型、页面和内容包实测另见 [验收记录](REAL-MODEL-RESULTS.md)；本次发布检查未重新调用模型。
